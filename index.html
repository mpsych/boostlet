Boostlet Reloaded

The four plugins from the Boostlet Reloaded paper. Open a page that runs NiiVue with a volume loaded, such as the OpenNeuro file viewer or Slice:Drop Reloaded, then click the bookmark. A short note appears while a plugin loads and tells you if it could not start.

Labeled 9×9 grid of the voxel values around the crosshair, in the plane you clicked. Needs NiiVue.

Mean, standard deviation, minimum, maximum and quartiles of the same 9×9 patch. Needs NiiVue.

Code editor that reads and changes the volume with NumPy style JavaScript (numpy-ts), with one click undo. Needs NiiVue.

Links several viewers in real time: crosshair, view, colormap, windowing and the shared NumPy editor. Anyone with the room code can join, so only share it with people you trust. Needs NiiVue.

Original examples (2025)

From the first Boostlet paper. These are not maintained. The grey text under each one says what it needs.

Edge filter on the rendered image. Click the result to restore the viewer. Any supported viewer.

Histogram of the pixels currently on screen. Any supported viewer.

Brain tissue segmentation that runs in the browser. Needs NiiVue.

Shows the loaded surface mesh in augmented reality. Needs NiiVue with a mesh loaded, a webcam and a Hiro marker.

Shows the loaded fiber tract in augmented reality. Needs NiiVue with a tract loaded, a webcam and a Hiro marker.

Chat with a language model that runs in your browser. The panel can take half a minute to appear. Needs WebGPU. Does not use the viewer.

Drop a skin photo to classify it. Does not use the viewer.

Loads compressed fiber tracts (.tko). Currently not working on OpenNeuro or Slice:Drop Reloaded.

Classifies a 2D photo loaded in NiiVue. Does not work on medical volumes.

Captions the current slice with a hosted model. The hosting service no longer responds.

  1. Which visualization frameworks are supported?
  2. Currently Cornerstone2D.js and NiiVue.js. Others like openseadragon.js, slicedrop.com, Papaya are in the works! BrainChop we are coming for you - j/k :))))
  3. What can BOOSTLETs really do?
  4. Any processing with any library is possible! The examples above use plotly.js or ONNX.js. BOOSTLETs provide methods that allow data access and interaction across different frameworks through JS injection. This is all client-side, unless you send some requests to a server.
  5. Do the algorithms work on the real data?
  6. If the visualization framework supports it, we access the real data. If not, we fall back to canvas imagedata but we are working with the developers of the frameworks to fix that :)
  7. How can I write my own BOOSTLET?
  8. Check out the code for the examples above - there is always the top block that imports boostlet.min.js and then a run method for the processing. It is pretty straight forward (especially the sobel.js and plotly.js examples) and any library or processing is possible.
  9. How can I contribute to BOOSTLET development?
  10. Fork the repo :) We use parcel.js as the build system. PRs are very welcome :)
